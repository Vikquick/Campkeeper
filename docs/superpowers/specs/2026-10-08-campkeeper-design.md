# Campkeeper — спецификация

Дата: 2026-10-08. Статус: утверждена в обсуждении, ждёт ревью файла.

## 1. Цель и рамки

Аддон для **World of Warcraft: Forever** (клиент 1.60.1, `## Interface: 16001`, проект `WOW_PROJECT_CAMELOT = 18`) о системе лагерей. Публикация на CurseForge и Wago. Запуск игры — 4 ноября 2026, версия 1.0 выходит к этой дате.

Ниша: конкуренты (S'more Skills — пауза, CampFirePin, AzerothArchive Campsite Tracker — десятки загрузок) делают только поиск лагерей. Campkeeper закрывает весь цикл: «я у лагеря» → «чего не хватает и что я могу поставить» → таймеры → поиск и обмен → планирование лагеря группы → учёт по альтам.

Не входит в 1.0: учёт слоёв (layering), источники выпадения чертежей, любая работа с боевыми данными.

## 3. Архитектура

Один аддон `Campkeeper`, модули в одном пространстве имён (AceAddon), библиотеки встроены через `.pkgmeta`:
AceAddon-3.0, AceDB-3.0, AceComm-3.0, AceSerializer-3.0, AceConfig-3.0, AceConsole-3.0, ChatThrottleLib, HereBeDragons-2.0 + HereBeDragons-Pins-2.0, LibDataBroker-1.1, LibDBIcon-1.0.

```
Campkeeper/
  Campkeeper.toc
  Data/Catalog.lua        -- генерируется tools/gen_catalog.py, руками не правится
  Core/Util.lua           -- безопасные вызовы, секреты, время, координаты
  Core/Catalog.lua        -- доступ к каталогу, локализованные имена из клиента
  Core/CampState.lua      -- машина состояний по аурам
  Core/BenefitsParser.lua -- разбор подсказки «Бонусы лагеря»
  Core/OwnCamp.lua        -- свой лагерь и перезарядка
  Core/CampStore.lua      -- известные лагеря, слияние, очистка
  Core/Professions.lua    -- профессии, навыки, умения, предметы в сумках
  Comm/Protocol.lua       -- кодирование и проверка сообщений
  Comm/Comm.lua           -- каналы, очередь, троттлинг, синхронизация гильдии
  UI/Panel.lua            -- панель лагеря
  UI/Pins.lua             -- пины карты и миникарты
  UI/Window.lua           -- окно: Каталог / Планировщик / Альты
  UI/Planner.lua          -- алгоритм планировщика (без UI-зависимостей)
  UI/Options.lua          -- AceConfig
  UI/Alerts.lua           -- оповещения
  Locales/                -- только строки интерфейса (имена объектов — из клиента)
```

Правило зависимостей: `Core` и `Comm/Protocol` и `UI/Planner` не трогают фреймы и тестируются вне игры; UI подписывается на сообщения ядра (AceEvent-подобные callbacks `Campkeeper:Fire("CAMP_STATE_CHANGED", ...)`).

## 4. Ядро

### 4.1 Каталог
`Data/Catalog.lua` содержит только ID и связи:
`objects[key] = { profession = <skillLineID>, tier = 1|2|3, skill = 20|140|300, itemID, placeSpellID, craftSpellID, replaces = <key T1>|nil, kind = "buff"|"vendor"|"station"|"gather", exclusiveWith = { classBuffSpellIDs } }`;
`fires[tier] = { itemID, placeSpellID, craftSpellID, skill, slots, burn = 600 }`.
Имена и описания — `C_Item.GetItemNameByID` / `C_Spell.GetSpellName` / `C_Spell.GetSpellDescription` с ожиданием загрузки (`ContinueOnItemLoad`, `SPELL_DATA_LOAD_RESULT`). Генератор берёт `out/scan.json` и таблицу тиров из исследования.

### 4.2 Машина состояний (`CampState`)
`AWAY` → `NEAR` (есть 1283391) → `SITTING` (есть 1229739; `remaining`) → `BUFFED` (есть 1229741; `expiresAt`, `objects`).
Источник — `UNIT_AURA` для `player` с `updateInfo` (added / updated / removed), полный пересбор при `isFullUpdate` и при входе.
В бою (`InCombatLockdown()` или секретные значения) состояние заморожено; пересбор на `PLAYER_REGEN_ENABLED`.
Каждый переход публикует `CAMP_STATE_CHANGED(old, new, info)`.

### 4.3 Разбор «Бонусов лагеря»
`C_TooltipInfo.GetUnitBuffByAuraInstanceID("player", id)` → строки после заголовка; формат «<Имя>: <эффект>». Имя сравнивается с локализованными именами объектов каталога (без регистра, без цветовых кодов). Нераспознанные строки → `unknown` + отладочный лог. Если подсказка пуста (данные не загружены) — повтор через 1 с, до 5 раз. Ответ на Q1 определяет, сопоставлять ли и с именами T2/T3.

### 4.4 Свой лагерь и перезарядка (`OwnCamp`)
`UNIT_SPELLCAST_SUCCEEDED` (unit `player`) по `placeSpellID` костров → новый свой лагерь `{ mapID, x, y, tier, placedAt = GetServerTime(), expiresAt = placedAt + 600 }`; по `placeSpellID` объектов → добавить объект к ближайшему своему лагерю (≤ 30 ярдов) и отметить время установки.
Перезарядка: `C_Container.GetItemCooldown(itemID)` любого походного предмета в сумках; результат `readyAt` хранится в `char` для таблицы альтов. Если предметов в сумках нет — последнее известное значение.
Ошибки установки (`UI_ERROR_MESSAGE` с кодами 57/58 во время каста установки) → подсказка на панели.

### 4.5 Хранилище лагерей (`CampStore`)
Запись: `{ id, mapID, x, y, tier?, objects = set, placedAt?, expiresAt?, lastSeen, source = "self"|"party"|"guild"|"channel"|"seen", reporters = set, confirmed = bool }`.
Слияние: та же карта и расстояние ≤ 30 ярдов (через HereBeDragons `GetWorldDistance`) и пересечение по времени жизни → одна запись; состав объектов объединяется, точнее координаты — от `self`.
Очистка: `expiresAt` прошло, или нет `expiresAt` и `lastSeen` старше 10 мин. Лимит 200 записей (удаляются самые старые из `channel`).
`confirmed = true`, если источник `self`/`seen`/`party`/`guild` или ≥ 2 разных `reporters` из канала.

### 4.6 Сохранения (AceDB)
- `global.camps` — `CampStore`.
- `global.chars[realm-name]` — профессии и навыки, походные предметы в сумках, умеет крафтить (по рецептам при `TRADE_SKILL_SHOW`), чертежи, `cooldownReadyAt`, `boostedRestUntil`.
- `char.lastBenefits` — состав и `expiresAt`.
- `profile` — позиция и видимость панели, оповещения, каналы обмена, приоритеты планировщика.

## 5. Панель и таймеры

Компактный фрейм у баффов; перемещается с Shift; поддержка позиции из настроек.
- Показ: при `NEAR`/`SITTING`/`BUFFED`, скрытие через 10 с после `AWAY`; всегда скрыта в бою.
- Заголовок: тир костра, «N/слоты», «гаснет через», если известно.
- Строки объектов: иконка, имя, эффект; состояния «стоит» / «можно поставить» (есть предмет, хватает навыка, перезарядка готова) / «перекрыто» (на игроке классовый бафф из `exclusiveWith`).
- «Можно поставить»: строка — `SecureActionButtonTemplate` с `type=item`, `item=<itemID>`; атрибуты меняются только вне боя.
- Полоса сидения: «Сядьте у костра» → отсчёт 60 с → «Бонусы получены, ЧЧ:ММ».
- Таймеры: перезарядка (персонаж и альты в подсказке кнопки миникарты), остаток бонусов, свой костёр, Boosted Rest (после Q3).
- Оповещения (каждое отключаемо): лагерь рядом; бонусы получены; бонусы кончатся через 5 мин; перезарядка готова; свой костёр гаснет через 1 мин.

## 6. Карта и обмен

### 6.1 Пины
HereBeDragons-Pins: карта мира и миникарта; иконка по тиру, прозрачность для `confirmed = false`; лагеря ≤ 500 ярдов держатся на краю миникарты. Подсказка: объекты, возраст, остаток, источник. Клик: `C_Map.SetUserWaypoint` + супертрек, либо TomTom, если загружен.

### 6.2 Протокол
Префикс `CAMPK`. Сообщение — AceSerializer-строка таблицы:
`{ v = 1, t = "CAMP", id = "<последние 8 символов GUID владельца>-<placedAt>" (для замеченных без владельца: "<GUID сообщившего>-<lastSeen>"), m = mapID, x = 0..1000, y = 0..1000, tier = 1..3|nil, o = <битовая маска объектов>, p = placedAt|nil, e = expiresAt|nil }`
`{ v = 1, t = "SYNC" }` — запрос в гильдии; `{ v = 1, t = "PROF", p = { [skillLineID] = skill } }` — профессии для планировщика (только группа).
Порядок битов маски фиксирован ключами каталога; новые объекты добавляются только в конец. Несовместимая мажорная версия → игнор + одно уведомление «обновите аддон».

### 6.3 Каналы и отправка
- `GUILD`, `PARTY`/`RAID`, и скрытый канал `Campkeeper` (через `JoinTemporaryChannel`, убран из всех окон чата; отключаемый). Если Q5 покажет, что сообщения в канал не доходят, общий обмен отключается, остаются гильдия и группа.
- Отправка только по событиям: установка своего костра/объекта; переход в `BUFFED` (состав узнан); `SYNC` при входе в гильдию — отвечают ≤ 2 игрока со случайной задержкой 2–8 с, только свежими лагерями.
- При `C_ChatInfo.InChatMessagingLockdown()` или `AreOutgoingAddonChatMessagesRestricted()` — очередь до снятия ограничения.
- Всё через ChatThrottleLib, приоритет `BULK`.

### 6.4 Проверка входящих
Отбрасывать: > 3 сообщений в минуту от отправителя; координаты вне 0..1000; `p` в будущем (> 60 с) или лагерь истёк; неизвестный `mapID`; отправитель в игноре; дубликаты `id`. Источник записи — канал, из которого пришло сообщение.

## 7. Окно

Кнопка миникарты (LibDBIcon) и `/ck`; нативный шаблон окна Blizzard; вкладки:
1. **Каталог** — профессия × тир: иконка, имя, эффект, навык, «заменяет», «умею» (кэш рецептов при открытии профессии).
2. **Планировщик** — профессии участников (из `PROF` + ручной ввод), число слотов, роль группы (прокачка / подземелье / крафт). Алгоритм (`UI/Planner.lua`, чистая функция): исключить баффы, которые дают классы группы; ранжировать оставшиеся объекты по весам роли; жадно заполнить слоты, предпочитая высший доступный тир; выдать «кто что ставит». Кнопка «В чат группы».
3. **Альты** — персонажи аккаунта: профессии/навыки, походные предметы, умеет крафтить, чертежи (выучен/нет; источник — после Q4), перезарядка.

Настройки — AceConfig в меню «Модификации».

## 8. Ошибки и устойчивость

Все вызовы API — через безопасную обёртку; секретные значения и незагруженные данные пропускаются с повтором. Нераспознанные строки бонусов и неизвестные объекты — в отладочный лог (`/ck debug`, кольцевой буфер 200 записей). Ни одна ошибка обмена не влияет на панель и таймеры.

## 11. Риски

| Риск | Мера |
|---|---|
| Blizzard меняет ID/ауры в патчах беты | генератор каталога + `/fad scan camp`; отладочный лог неизвестного |
| Сообщения в канал ограничены | обмен через гильдию/группу остаётся |
| Мало установок → пустая карта | ценность без сети: панель, таймеры, планировщик, альты |
| Ложные лагеря из канала | доверие, подтверждение двумя игроками, лимиты |
| Защищённые действия в бою | кнопки установки меняются только вне боя; панель скрыта в бою |
