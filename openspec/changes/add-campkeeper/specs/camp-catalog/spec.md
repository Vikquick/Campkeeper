# Spec Delta

## Purpose

Справочник всех походных объектов и костров Forever. Остальные части аддона берут из него профессию, тир, требуемый навык, замены и эффекты, а игрок просматривает его во вкладке «Каталог».

## ADDED Requirements

### Requirement: Полнота каталога
Каталог SHALL содержать каждый походный объект трёх тиров для 12 профессий и три тира костров. Для каждого объекта указаны профессия, тир, требуемый навык, предмет, заклинание установки, заклинание изготовления и объект, который он заменяет. Для каждого костра указаны навык Кулинарии, число слотов и время горения.

#### Scenario: Объект T2 заменяет объект T1
- **WHEN** аддон запрашивает в каталоге «Наковальню»
- **THEN** каталог возвращает профессию «Кузнечное дело», тир 2, навык 140, и в поле замены — «Круг для заточки»

#### Scenario: Тиры костров
- **WHEN** аддон запрашивает в каталоге костры
- **THEN** каталог возвращает три тира с навыком Кулинарии 1, 140 и 220, со слотами 3, 5 и 10 и временем горения 600 секунд

### Requirement: Имена из клиента
Имена и описания объектов SHALL браться из данных клиента на языке игрока, а не из строк аддона. Пока данные клиента не загружены, каталог SHALL показывать временную подпись и заменять её, как только данные придут.

#### Scenario: Клиент на английском
- **WHEN** игрок с клиентом enUS открывает каталог
- **THEN** имена объектов показаны на английском без правок в коде аддона

#### Scenario: Данные предмета ещё не загружены
- **WHEN** аддон запрашивает имя предмета, которого нет в кэше клиента
- **THEN** вместо имени показана временная подпись, а после загрузки данных она заменяется на настоящее имя

### Requirement: Каталог воспроизводится из данных клиента
Каталог SHALL собираться генератором из результатов сканирования клиента и закреплённой таблицы тиров. Ручная правка собранного файла не допускается. Если в данных сканирования нет нужного объекта, генератор SHALL завершиться с ошибкой.

#### Scenario: Повторная сборка после патча беты
- **WHEN** разработчик заново сканирует клиент и запускает генератор
- **THEN** файл каталога пересобирается, и изменения ID видны в diff

#### Scenario: Объект пропал из данных
- **WHEN** в данных сканирования нет предмета, указанного в таблице тиров
- **THEN** генератор завершается с ненулевым кодом и называет пропавший объект

### Requirement: Вкладка «Каталог»
Окно SHALL содержать вкладку «Каталог» — таблицу «профессия × тир». В каждой ячейке показаны иконка, имя, эффект, требуемый навык, заменяемый объект и отметка «умею» для текущего персонажа.

#### Scenario: Отметка «умею»
- **WHEN** персонаж открывал окно профессии и знает рецепт «Магнетита»
- **THEN** в ячейке «Магнетит» стоит отметка «умею»

#### Scenario: Профессия не изучена
- **WHEN** у персонажа нет профессии «Алхимия»
- **THEN** объекты алхимии показаны, но без отметки «умею» и с требуемым навыком
