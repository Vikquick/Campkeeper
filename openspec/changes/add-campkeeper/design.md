# Design

## Context

Мотивация — в proposal.md (раздел Why). Подробный дизайн, согласованный в обсуждении, лежит в `docs/superpowers/specs/2026-10-08-campkeeper-design.md`, факты о клиенте — в `docs/research/2026-10-08-campsite-client-data.md`. Здесь записаны решения, которые определяют реализацию, и их альтернативы.

Что уже есть в репозитории:
- dev-аддон `ForeverApiDump` (дамп API, разведчик лагерей `/fad camp`, сканер ID `/fad scan camp`);
- `tools/fad.py` и `tools/test_fad.py` — тест аддона вне игры на lupa (Lua 5.1) с заглушками WoW API, без зависимостей кроме `lupa`;
- `out/scan.json` — результат сканирования; папка в git не хранится и пересобирается в игре.

Ограничения клиента: отдельного API лагерей нет, vignettes и GUID объектов нет, `PLAYER_CAMPING` при установке не приходит; в бою значения могут быть секретными; защищённые действия возможны только вне боя.

## Goals / Non-Goals

**Goals:**
- Логику (состояние, разбор бонусов, хранилище, протокол, планировщик) можно проверить вне игры, без клиента.
- Каталог пересобирается одной командой после патча беты.
- Ни одна часть, зависящая от непроверенного поведения беты (Q1–Q5), не блокирует остальные.

**Non-Goals:**
- Поддержка retail, Classic Era и других клиентов, кроме Forever.
- Учёт слоёв, источники выпадения чертежей, любые боевые данные (как в дизайн-документе).
- Автоматические UI-тесты фреймов: интерфейс проверяется чек-листом в бете.

## Decisions

### 1. Один аддон на Ace3 с модулями
Один аддон `Campkeeper`, внутри модули AceAddon в одном пространстве имён. Структура файлов — как в разделе 3 дизайн-документа, с одним отличием: планировщик переезжает из `UI/Planner.lua` в `Core/Planner.lua`, потому что это чистая функция без фреймов.
*Альтернативы:* набор отдельных аддонов (ядро + карта + окно) усложняет установку и синхронизацию версий; без Ace3 пришлось бы писать свои сохранения, сериализацию и настройки.

### 2. Чистое ядро с внедряемыми зависимостями
Модули `Core/*` и `Comm/Protocol.lua` не создают фреймы и не обращаются к глобальному API напрямую. Время, расстояние, чтение аур и подсказок, данные сумок они получают через `ns.api` — тонкую обёртку из `Core/Util.lua`. Изменения состояния ядро сообщает через CallbackHandler-1.0 (`ns.callbacks:Fire("CAMP_STATE_CHANGED", ...)`), а UI на них подписывается.
*Альтернатива:* модули, которые сами вызывают `C_UnitAuras`, проще писать, но в тестах пришлось бы подменять весь глобальный API.

### 3. Тесты: Python unittest + lupa
Тесты лежат в `tests/test_*.py` и запускаются командой `python -m unittest discover tests`. Общий `tests/wowenv.py` создаёт среду lua51, ставит заглушки WoW API (продолжая подход `tools/test_fad.py`), подгружает LibStub, CallbackHandler и AceSerializer из `Campkeeper/Libs/` и файлы аддона в порядке из `.toc`.
*Альтернативы:* busted требует luarocks, а на Windows его ставить хлопотно; pytest ничего не даёт по сравнению со стандартным unittest и добавляет зависимость.

### 4. Библиотеки: `.pkgmeta` + локальная загрузка
Библиотеки перечислены в `.pkgmeta` как externals и встраиваются BigWigs Packager при выпуске. Для разработки и тестов `tools/fetch_libs.py` читает те же externals и скачивает их в `Campkeeper/Libs/`; эта папка добавлена в `.gitignore`.
*Альтернатива:* хранить библиотеки в git — раздувает репозиторий и расходится с упаковкой.

### 5. Каталог: закреплённая таблица + данные сканирования
`tools/catalog_tiers.json` (в git) — источник истины по составу. В нём ключи объектов в фиксированном порядке, профессия (skillLineID), тир, предмет, тип объекта, несовместимые классовые баффы и веса для ролей планировщика. `tools/gen_catalog.py` берёт из `out/scan.json` заклинания установки (по заклинанию «Использование» предмета) и изготовления (по названию «Изготовить …»), проверяет требования навыка и пишет `Campkeeper/Data/Catalog.lua` (тоже в git). Порядок ключей одновременно задаёт порядок битов в протоколе. Тест генератора проверяет, что ключи из прошлой версии каталога не сдвинулись.
*Альтернатива:* искать связи только эвристиками по сканированию — тиры и замены в клиенте явно не связаны, без таблицы это ненадёжно.

### 6. Состояние только по аурам игрока
Состояние определяется по трём spellID (1283391, 1229739, 1229741), которые хранятся в каталоге, по событию `UNIT_AURA` с разбором `updateInfo`. Полный пересчёт выполняется при входе, при `isFullUpdate` и после боя.
*Альтернатива:* опрос по таймеру — лишняя нагрузка, при этом событий аур хватает.

### 7. Состав — из текста подсказки, а не из `points`
Числа `points` у «Бонусов лагеря» не совпадают с текстом (проверено разведкой), поэтому состав берётся из строк подсказки `C_TooltipInfo`. Имя сравнивается с именами объектов всех тиров. Если совпадения нет, ищется T1 из той же цепочки замен — так разбор работает при любом ответе на Q1.

### 8. Протокол на AceComm + AceSerializer
Сообщение — сериализованная таблица (раздел 6.2 дизайн-документа) с префиксом `CAMPK`, отправка через AceComm/ChatThrottleLib с приоритетом `BULK`. Описание лагеря укладывается в одно сообщение, поэтому сжатие не нужно.
*Альтернатива:* LibSerialize + LibDeflate экономят байты, но добавляют две зависимости ради сообщений, которые и так короче лимита.

### 9. Общий канал через временный канал
Аддон заходит в канал через `JoinTemporaryChannel("Campkeeper")` и убирает его из всех окон чата. Если проверка Q5 покажет, что addon-сообщения в пользовательский канал не доходят, общий обмен выключается флагом по умолчанию, а код остаётся.

### 10. Доверие к данным из канала
Подробности — в спецификации `camp-sharing` и `camp-map`. Свои, замеченные, групповые и гильдейские записи подтверждены сразу; записи из канала подтверждаются вторым сообщившим и показываются полупрозрачными до подтверждения. Так ложная метка одного игрока не выглядит как настоящая.

### 11. Защищённые действия
Кнопки установки — `SecureActionButtonTemplate` с `type=item`. Атрибуты меняются только вне боя: изменения в бою откладываются до `PLAYER_REGEN_ENABLED`. В бою панель скрыта целиком, поэтому кнопки не приходится прятать по отдельности.

### 12. Сохранения
Одна переменная `CampkeeperDB` (AceDB) с разделами `global.camps`, `global.chars[realm-name]`, `char.lastBenefits` и `profile` (раздел 4.6 дизайн-документа). В корне хранится `dbVersion = 1`, чтобы будущие версии могли выполнять миграцию.

## Risks / Trade-offs

- [Патч беты меняет ID или ауры] → каталог пересобирается одной командой; неизвестные строки и объекты попадают в отладочный журнал; перед каждым выпуском повторяется `/fad scan camp`.
- [Пользовательский канал не передаёт addon-сообщения] → общий обмен выключается, гильдия и группа работают; панель, таймеры, планировщик и альты от сети не зависят.
- [Мало установок — пустая карта] → основная ценность (панель, таймеры, планировщик, альты) доступна одному игроку.
- [Ложные лагеря из канала] → лимиты, проверка входящих, подтверждение вторым игроком, полупрозрачные пины.
- [Заглушки в тестах расходятся с настоящим API] → сигнатуры заглушек сверяются с `out/forever-reference.md`; каждая веха проверяется чек-листом в бете.
- [Короткий срок до 4 ноября] → задачи упорядочены по вехам: альфа (ядро, панель, таймеры), бета (карта, обмен), 1.0 (окно). Если не успеваем, 1.0 выходит без планировщика, а он переносится в 1.1.

## Migration Plan

Пользовательских данных пока нет, поэтому переносить нечего. Выпуск — по тегам git: `v0.1.0-alpha` (~20 октября), `v0.2.0-beta` (~28 октября), `v1.0.0` (4 ноября). GitHub Actions упаковывает и публикует сборку на CurseForge и Wago. Откат — повторная публикация предыдущего тега. Изменения формата сохранений после 1.0 проходят через `dbVersion`.

## Open Questions

Все вопросы проверяются в бете и не меняют ни спецификаций, ни задач: для каждого заложено поведение при любом ответе.
- **Q1.** Какое имя пишется в «Бонусах лагеря» для объекта T2/T3. Решение 7 работает в обоих случаях; ответ лишь уточняет, какой тир показывать.
- **Q2.** Радиус ауры «Кострище неподалеку». Нужен только для текста оповещения «лагерь рядом» и проверки радиуса слияния (30 ярдов).
- **Q3.** spellID ауры Boosted Rest. Если его не найти, таймер не показывается (спецификация `camp-timers`).
- **Q4.** Откуда берутся чертежи T2/T3 и как узнать, выучен ли чертёж. Если признака нет, показывается «неизвестно» (спецификация `alt-tracking`).
- **Q5.** Доходят ли addon-сообщения в пользовательский канал. Если нет, общий обмен выключается (решение 9).
